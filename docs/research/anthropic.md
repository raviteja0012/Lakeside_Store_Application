# Anthropic Claude platform: feature surface

Researched 2026-08-12 against the vendor's live documentation, not from memory. 62 capabilities.

**This is a reference catalog, not a plan.** What we adopt and what we decline, with reasons,
lives in [CAPABILITIES.md](../CAPABILITIES.md). The services actually wired up today live in
[PLATFORM.md](../PLATFORM.md). Re-check anything here before acting on it: vendor pricing and
feature names move, and this is a dated snapshot.

Scope note from the researcher:

> Anthropic Claude Developer Platform (Claude API), as documented at platform.claude.com and code.claude.com on 2026-08-12. All facts below were fetched live from the official docs during this research; anything I could not verify from a fetched page is explicitly flagged in plan_or_cost. Relevance notes are written for an app doing invoice vision extraction plus grounded Q&A over its own data (the Robinson's General Store pattern: PDF/photo invoice capture -> structured extraction -> ask-your-store over Supabase rows).


## Agents

| Capability | What it does | Plan or cost | Maturity |
|---|---|---|---|
| **Agent Skills (Messages API)** | Folders of instructions/scripts (SKILL.md with YAML frontmatter) loaded on demand into the code-execution container; Anthropic ships four prebuilt skills — pptx, xlsx, docx, pdf — and custom skills upload via the Skills API. For a store app the xlsx skill is the cheapest route to 'export this month's invoice ledger as a spreadsheet'. | Beta headers code-execution-2025-08-25 + skills-2025-10-02 (+ files-api-2025-04-14 for download). Passed via container.skills alongside a code_execution tool. Up to 8 skills per request on the Messages API. Cost = tokens + code-execution container time (free with web search/fetch, else 1,550 free hours/month then $0.05/hour). Custom skill upload limit: 30 MB uncompressed, name ≤64 chars, description ≤1024 chars. | Beta |
| **Claude Agent SDK** | Claude Code packaged as a library for Python and TypeScript — built-in Read/Write/Edit/Bash/Glob/Grep/WebSearch tools, the agent loop, context management, hooks, subagents, permissions, sessions, skills and plugins, running in YOUR process on YOUR infra. Distinct from both the Messages API tool runner and Managed Agents. | Free library; you pay standard API token costs. Python and TypeScript only (drive it from other languages by running the CLI with -p --output-format json). Governed by Anthropic's Commercial Terms. Anthropic does not permit third-party products to offer claude.ai login or subscription rate limits through the SDK — use API-key auth. Branding rules: you may say 'Claude Agent' or 'Powered by Claude', not 'Claude Code'. | GA |
| **Claude Managed Agents** | Anthropic runs the agent loop AND hosts a per-session sandbox with bash, file ops, web search/fetch and MCP; you create a versioned Agent, an Environment, then Sessions that stream events over SSE. The alternative to hand-writing your own extraction/reorder agent loop, at the cost of losing ZDR eligibility. | Beta header managed-agents-2026-04-01. Billed on two dimensions: all tokens at standard model rates (prompt caching multipliers apply; web search $10/1k) PLUS session runtime at $0.08 per session-hour, metered only while status is 'running'. Session runtime REPLACES code-execution container-hour billing. Batch discount does NOT apply; not available on Bedrock or Google Cloud. NOT ZDR-eligible and NOT covered by a HIPAA BAA — session transcripts persist until you delete them. Rate limits: 300 RPM create, 1,200 RPM read. Optional hard per-session dollar budget via budget.max_list_cost. | Beta |
| **Managed Agents: memory stores, vaults, scheduled deployments, self-hosted sandboxes** | Supporting resources: memory_stores (workspace-scoped text documents FUSE-mounted into the session, with immutable versions and redaction), vaults (MCP OAuth credentials plus environment_variable secrets substituted at egress so the sandbox never sees them), deployments (cron-scheduled autonomous sessions), and self_hosted environments (tool execution on your own infra via an outbound-polling worker). The vault mechanism is the right answer if a store agent ever needs a supplier API key. | All under beta header managed-agents-2026-04-01; billed as part of Managed Agents session tokens + runtime. Max 1,000 scheduled deployments per org; cron is minute-granularity with up to 9 minutes of load-spreading jitter. Self-hosted sandboxes do not yet support memory_store resources or environment_variable credentials, and are not available on Claude Platform on AWS. MCP tunnels and 'dreaming' are a narrower research preview requiring a request form. | Beta |

## Context

| Capability | What it does | Plan or cost | Maturity |
|---|---|---|---|
| **1M-token context window** | Opus 5, Opus 4.8/4.7/4.6, Sonnet 5, Sonnet 4.6, Fable 5 and Mythos 5 all carry a 1M-token context window as the DEFAULT, with 128k max output; Sonnet 4.5, Opus 4.5 and Haiku 4.5 are 200k. Enough to hold a whole month of invoices in one prompt, though the docs warn about 'context rot' — recall degrades as tokens grow, so curation still matters. | No beta header and NO long-context price premium — a 900k-token request bills at the same per-token rate as a 9k one. Caching and batch discounts apply across the full window. Note that Claude 4.7+ tokenizer produces ~30% more tokens for the same text, so the effective character capacity is lower than on Sonnet 4.6. | GA |
| **Context awareness (token budget injection)** | On Sonnet 5, Sonnet 4.6, Sonnet 4.5 and Haiku 4.5 the API automatically injects <budget:token_budget> and post-tool-call <system_warning> tags so the model tracks its remaining context. Nothing to enable; Opus 4.7+ and Fable 5 do not get these and use task budgets instead. | Free, automatic. You never send these tags yourself. | GA |
| **Context editing** | Prunes rather than summarizes: clear_tool_uses_20250919 drops old tool results (default trigger 100,000 input tokens, keep last 3, optional clear_tool_inputs) and clear_thinking_20251015 drops thinking blocks. Handy for a long invoice-processing loop where old tool payloads are dead weight. | Beta header context-management-2025-06-27. Free (it reduces billed input). Works on all supported Claude models. Tool-result clearing invalidates prompt cache; thinking clearing preserves it if blocks are kept. When combining, clear_thinking_20251015 must be listed first. | Beta |
| **Mid-conversation system messages** | Append {"role":"system", …} entries to messages[] to deliver operator instructions mid-conversation without editing the top-level system prompt. Preserves the cached prefix and is the non-spoofable operator channel (unlike embedding instructions in a user turn). | No beta header. Per the prompt-caching docs, supported on Claude Fable 5, Mythos 5, Opus 4.8 and later, and Sonnet 5. The claude-api reference bundled with this environment states it is NOT on Claude Sonnet 5 while the docs page lists it — sources conflict, so catch the 400 ("role 'system' is not supported on this model") and fall back to a user-turn reminder. | GA |
| **Server-side compaction** | context_management.edits with {type:"compact_20260112"} makes the API summarize earlier turns server-side when input tokens cross a trigger, returning a compaction content block you must pass back on subsequent requests. The recommended way to run a long ask-your-store conversation past the context limit without writing your own summarizer. | Beta header compact-2026-01-12. Default trigger 150,000 input tokens (minimum configurable 50,000). Compaction costs an extra sampling pass billed separately — top-level input_tokens/output_tokens cover only the non-compaction iteration, so sum usage.iterations for true cost. Optional pause_after_compaction and custom instructions. Available in beta on Claude API, Claude Platform on AWS, Bedrock, Google Cloud, and Foundry. | Beta |

## Cost control

| Capability | What it does | Plan or cost | Maturity |
|---|---|---|---|
| **300k extended output for batch (output-300k-2026-03-24)** | Beta header that raises the max_tokens cap from 128k to 300,000 for batch requests on Opus 5, Opus 4.8/4.7/4.6, Sonnet 5, Sonnet 4.6. Relevant only if you generate very long documents; a single 300k generation can take over an hour against the 24-hour batch window. | Standard batch pricing (50% off). Beta header: output-300k-2026-03-24. | Beta |
| **Cache pre-warming with max_tokens: 0** | Send a request with max_tokens: 0 to run prefill only — it writes the cache and returns immediately with empty content and stop_reason max_tokens, at zero output-token cost. Useful at worker boot so the first real invoice/question doesn't eat the cold-write latency. | Costs one cache write (1.25x or 2x input). Rejected with stream:true, thinking enabled, output_config.format, forced tool_choice, or inside a Message Batch. | GA |
| **Message Batches API** | Submit up to 100,000 Messages requests asynchronously (POST /v1/messages/batches), poll for completion, stream results keyed by custom_id. For an invoice app this is the obvious home for overnight backfills, bulk re-extraction after a prompt change, and periodic reconciliation runs. | Flat 50% discount on ALL token usage (input, output, cache). Limits: 100,000 requests or 256 MB per batch, whichever comes first; most finish <1 hour, hard expiry at 24 hours; results retrievable for 29 days. Not supported inside a batch: stream, speed (fast mode), store, previous_thread_event_id, cache_hint, context_hint, max_tokens: 0, research_preview_2026_02. Batch rate limits are separate from Messages API limits. | GA |
| **Prompt caching** | Caches a prompt prefix (tools → system → messages, in that render order) so repeated content bills at ~10% of input price; either automatic (single top-level cache_control) or explicit per-block breakpoints, max 4 per request, 5-minute or 1-hour TTL. This is the single highest-leverage cost lever for grounded Q&A: cache the store schema + extraction rubric + tool defs once and pay 10% on every subsequent question. | 5m cache write = 1.25x base input; 1h cache write = 2.0x; cache read = 0.1x. Break-even after 1 read (5m) or 2 reads (1h). Minimum cacheable prefix is model-specific and NOT monotonic: 512 tokens (Opus 5 / Fable 5 / Mythos 5), 1024 (Opus 4.8, Sonnet 5, Sonnet 4.6, Sonnet 4.5), 2048 (Opus 4.7, Haiku 3.5), 4096 (Opus 4.6, Opus 4.5, Haiku 4.5). Under-threshold prompts silently do not cache. Multipliers stack with Batch and data-residency pricing. | GA |
| **Service tiers / Priority Tier** | service_tier request parameter ("auto" default, "standard_only") selects between committed Priority capacity and standard best-effort capacity; Priority targets 99.5% uptime with prioritized compute. Not an option for a new build. | Priority Tier capacity commitments are NO LONGER AVAILABLE FOR PURCHASE — only orgs with an existing contract can use it, through their contract end date. Priority is unsupported on Claude Opus 5, Claude Sonnet 5, Claude Mythos 5, and Mythos Preview. Burndown: cache read 0.1 tok/tok, 5m cache write 1.25, 1h write 2.0, inference_geo:"us" 1.1. | Deprecated for new customers |
| **Spend limits and workspace rate limits** | Set an org spend limit below your tier's cap in Console → Billing, and set per-workspace spend/RPM/ITPM/OTPM limits so one workspace can't starve the others. Practical guardrail for a small store deployment: cap the workspace so an extraction loop bug can't run up a bill. | Free. Tier caps: Start $500/mo, Build $1,000/mo, Scale $200,000/mo. You cannot set limits on the default workspace; unset workspace limits inherit the org limit; org-wide limits always apply even if workspace limits sum higher. Batches may go slightly over a configured spend limit due to concurrency. | GA |
| **Token counting API (/v1/messages/count_tokens)** | Returns input_tokens for a fully-formed request including system prompt, tools, images and PDFs, before you send it. Use it to reject oversized invoice PDFs up front and to pre-estimate cost per document. | Free, with its own RPM limits (Start 2,000 / Build 4,000 / Scale 8,000) that do not draw on Messages limits. Counts are estimates and are model-specific — Claude 4.7+ models use a newer tokenizer producing ~30% more tokens for the same text, so never reuse counts measured on an older model. Do NOT use tiktoken. | GA |
| **Usage & Cost Admin API** | GET /v1/organizations/usage_report/messages returns token buckets (uncached input, cache creation, cache read, output, server tool use) at 1m/1h/1d granularity; GET /v1/organizations/cost_report returns USD costs at daily granularity. Group/filter by model, workspace, API key, service_tier, context_window, inference_geo, and speed — this is how you'd attribute cost per store or per feature. | Free; requires an Admin API key. Data typically appears within ~5 minutes. Bucket limits: 1m default 60 / max 1,440; 1h default 24 / max 168; 1d default 7 / max 31. Poll at most ~1/min sustained. Costs are decimal strings in cents. Priority Tier costs are NOT in the cost endpoint. Code execution appears in cost (as 'Code Execution Usage') but not in the usage endpoint. Not available on Claude Platform on AWS. Claude Enterprise orgs use a separate Analytics API key instead. Off-the-shelf integrations exist for CloudZero, Datadog, Grafana Cloud, Honeycomb, Vantage. | GA |

## Governance

| **Vision (image input)** | Accepts JPEG/PNG/GIF/WebP as base64, URL, or Files API file_id; images are billed in 28x28-pixel visual-token patches (⌈w/28⌉ × ⌈h/28⌉). Limits: 8000x8000 px max dims; 10 MB/image base64 on Claude API (5 MB on Bedrock/Google Cloud); 100 images/request on 200k-context models, 600 on 1M-context models; >20 images per request triggers a stricter per-image dimension cap (resize to ≤2000px). | GA |

## Output control

| Capability | What it does | Plan or cost | Maturity |
|---|---|---|---|

## Privacy

| Capability | What it does | Plan or cost | Maturity |
|---|---|---|---|
| **Data retention and zero data retention (ZDR)** | By default Anthropic does not retain conversation content for the Messages and Token Counting APIs, and retained data is NEVER used for model training without express permission. ZDR is an org-level arrangement (contact sales) under which prompts and responses are not stored at rest after the response returns. | ZDR is contractual, not self-serve. NOT covered by ZDR: Console/Workbench, Claude Managed Agents, Files API, MCP connector, code execution, consumer Claude plans, Claude Teams/Enterprise interfaces, Claude for Excel, third-party integrations, and CORS (browser calls must proxy through your backend). | **HIPAA readiness** | Signed BAA plus a HIPAA-enabled org lets you process PHI through eligible Claude API features, with encryption, access controls and audit logging rather than immediate deletion; the API returns a 400 naming any non-eligible feature in the request. Not needed for a Canadian retail store, but relevant if the same platform ever handles health data. | Self-serve standard BAA available in Console → Settings → Privacy for eligible orgs, or a negotiated BAA via sales. Enablement is PERMANENT and cannot be disabled by an admin. Not covered: Claude Code, Console/Workbench, Bedrock, Google Cloud, Claude Platform on AWS, Microsoft Foundry, consumer plans, and most beta features. Never put PHI in JSON schemas (structured outputs / strict tools) — schemas cache separately from message content. | GA |

## Reasoning

| Capability | What it does | Plan or cost | Maturity |
|---|---|---|---|
