Requirements note

Vendor details: showing only what applies

The ordering questions you asked for in July are saved correctly. Three screens are not reading them back. Here is what is happening and what I would like to fix.

Robinson's General Store · for Ravi Kiran · 11 August 2026

What I need from you

  1. A yes or no on the fix described below.
  2. One choice: should the app stay quiet about vendor questions nobody has answered yet, or should it be able to show you the list of what is still blank?

What is working

Every vendor can now record the four ordering facts you asked for on 31 July and 5 August:

Minimum order Summer order timeline Location of the order Reorder status and comments

All four are optional on purpose. There are about 130 vendors on file and nobody is going to fill these in for all of them in one sitting. The vendor page already hides the ones that have not been answered, so you never see a screen full of blanks.

What is not working

Nothing is lost. The answers are in the database. The problem is that each screen was told separately which vendor details to load, and they were told different things.

Three gaps

Ask the store cannot answer ordering questions

You can type the answer into a vendor, then ask the store about it and be told it is not on file.

You

When do I place the summer order for Lawson?

App

That is not recorded for this vendor.

It is recorded. The Ask page simply never loads that field, so it answers honestly from what it can see.

The reorder summary is blind to the same fields

When the app writes its reorder summary it cannot take the minimum order or the order timeline into account, for the same reason.

The vendor list shows none of it

To find out which vendors have a January deadline you have to open them one at a time. The directory does not load those fields at all.

What each screen loads today. Eight places in the app ask for vendor details and no two ask for the same set.

What I would like to build

One list of vendor questions, written down once, in your words. Each entry says what the question is called on screen, whether the answer is a dollar figure, and what to do when it is blank. Every screen then reads that one list instead of keeping its own.

What changes for you

  • Ask the store starts answering questions about minimums, timelines and reorders.
  • The reorder summary can use them when it works out what to suggest.
  • The vendor directory can show ordering facts, so you can scan for the January deadlines without opening every vendor.
  • Every screen describes a vendor the same way, using the same words for the same thing.
  • Adding a new vendor question later becomes one small change rather than five, so the next round of your feedback is quicker to build.

What does not change

  • Nothing to re-enter. No change to the database and no data entry.
  • The fields, the wording and the rules you approved in July stay exactly as they are, including the minimum order that cannot be both an amount and "no minimum".
  • Blank answers stay hidden by default. A vendor nobody has been asked about still shows a clean page.
  • Staff still never see the minimum order, because it is a dollar figure.

The choice I need from you

Today a vendor question with no answer is invisible. That is right for a page you are reading. It is unhelpful when you want to know how much is still blank across the roughly 130 vendors. This fix makes the second option cheap, so it is worth deciding now rather than later.

Option A. Leave it as it is. Blank questions stay hidden everywhere. Simplest, and nothing on screen changes for staff.

Option B. Add a "not answered yet" view. A list you can open showing which vendors are still missing a minimum order, a timeline, and so on, so the gaps can be filled a few at a time over the season.

My recommendation is B. The information is only useful once most vendors have it, and right now there is no way to see how far along that is.

Cost and risk

  • Effort. One build round. No database script for you to run and no downtime.
  • Risk. Low. The rules that protect money and hide costs from staff are not being touched, only the list of what each screen loads.
  • If you say no. Everything keeps working exactly as it does today. The three gaps above stay, and the Ask page keeps saying that ordering details are not on file.
